01 / WORK SAMPLE

Diagnose before changing

Scenario: a remote finance user can open an Excel file in the browser but receives “Access denied” in the desktop workflow. A reporting deadline is in two hours. All names, times and observations below are fictional.

Service record

FieldExample entry
Ticket / priorityDEMO-1042 / High: one deadline-sensitive user; browser workaround available
ScopeOne user, one shared workbook; no wider outage reported
Initial evidenceBrowser opens the file with the work account; desktop shows another signed-in identity
First decisionConfirm account mismatch before changing permissions
Owner / next updateAssigned support analyst / 09:30 WAT

Investigation sequence

  1. Confirm the exact file URL, error text, application version, affected account and recent changes. Ask whether the user needs view or edit access.
  2. Check whether colleagues are affected and whether Microsoft 365 service health shows a relevant incident. Confirm the user is using the approved work identity.
  3. Compare browser and desktop behaviour with the same account and file. Review effective file/folder/site access only with authorised administration rights.
  4. In this scenario, the browser succeeds and the desktop uses a different account. Agree a safe point to save and close work, then switch the desktop application to the correct work account.
  5. Retest the original task. Do not broaden permissions or use public sharing as a shortcut. If the same-account failure persists, capture sanitised evidence and escalate.

Customer update

“Thanks for showing me the error. The file opens in your browser, so you have a way to continue while I check the desktop sign-in. I’ll update you by 9:30, even if the investigation is still in progress.”

Document the result and close well

Illustrative continuation: the account mismatch is corrected with the user present. This is a synthetic outcome, not a claim about a real client incident.

Closure criteria

  1. The original workbook opens under the intended work identity.
  2. A permitted edit saves and is visible after reopening; existing access restrictions remain intact.
  3. The user confirms the original reporting task can continue.
  4. Record scope, diagnosis, action, verification, residual risk and follow-up in the ticket.

Escalation package

If unresolved: provide the business impact, exact error, timestamp/timezone, affected workload and account type, relevant service-health reference, same-account test results and steps already taken. Exclude passwords, access tokens and document contents.

Companion case: Outlook cannot connect

Establish whether the fault affects one desktop client or several users. Check service health and browser access. Compare identity, connectivity and recent changes before repairing the client. Preserve local-only data before a profile rebuild; do not reset MFA or remove a mailbox as a first response.
